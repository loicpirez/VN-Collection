# Round 9 PostgreSQL migration - 2026-08-24

This round tracks a complete PostgreSQL migration, not a driver-only proof of
concept. Current runtime introspection shows 50 legacy SQLite tables plus the
new `app_job_lock` table, 74 explicit indexes, 263 exported database
functions, and 334 source/test files importing database
surfaces. SQLite-specific behavior includes PRAGMAs, `INSERT OR REPLACE`,
`json_each`, `ATTACH`/`DETACH`, `sqlite_master`, FTS, and `lastInsertRowid`.

Completion means PostgreSQL is the production source of truth, all application
flows use the asynchronous persistence contract, the real SQLite database can
be migrated with verified row counts and relationships, backup/restore works
for PostgreSQL, and the complete app/test/browser gates pass. A partial hybrid
that silently continues to require SQLite is not completion.

## Runtime conversion progress

The following domains now select SQLite or PostgreSQL through typed asynchronous
repositories: application settings, owner-safe job locks, AliceNet inventory,
canonical VN writes and stock-specific VN reads, generic stock offers and
provider statuses, stock aliases and manual sources, stock title resolution,
stock refresh queues, and durable stock-batch progress. The stock refresh routes,
summary, recent activity, aliases, sources, Eroge Price candidate operations,
queue pagination, download-status polling, and download-status SSE now await
those contracts.

Evidence gathered against the isolated PostgreSQL 16 database
`vndb_collection_migration_dev`:

- `yarn db:postgres:smoke` passed with AliceNet, VN materialized indexes, stock
  offers/statuses/aliases/sources, three queue scopes, title cache, and durable
  job schema round-trips.
- Identical SQLite/PostgreSQL contracts now cover collection membership and
  ordering, canonical VN writes/reads, wishlist status, tag indexes, textual
  search, compare credits, places and branch stock, generic stock snapshots,
  aliases/sources/queues/freshness, owned editions, shelf cells/front displays,
  physical bundles, release-platform metadata, and aspect provenance. The
  isolated PostgreSQL suite passes 24/24 scenarios.
- A Next.js server configured with `DATABASE_BACKEND=postgres` returned HTTP 200
  for download status, per-VN stock, collection/reading/recent queues, stock
  summary, and alias add/delete. Warm application-code times were 7 to 30 ms.
- Focused SQLite compatibility suites pass for snapshots, summaries, stock
  routes, durable jobs, cancellation, and SSE. Full coverage and browser gates
  remain open and are not implied by this progress note.
- The ordered migrations through `0007_query_plan_indexes` migrated and
  independently verified all 405,242 rows from the real SQLite database. All
  28 contractual JSON-column checks passed with zero quarantined values; the
  verifier also proved that source-absent optional tables and columns remained
  empty in PostgreSQL.
